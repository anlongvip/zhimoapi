# 人工开票功能与宝塔 Docker 上线说明

## 功能

用户在侧栏「发票申请」选择已支付订单，填写公司名称、税号及可选的开户行、账号、地址、电话和备注。多笔订单可以合并，默认最低金额为 500 元。管理员在「发票管理」调整最低金额、开关及开票说明。

第一版仅支持人民币易支付充值订单，包括旧版记录中没有支付商标识的支付宝、微信及 QQ 钱包订单。上线前确认你的易支付收款币种确实为人民币。Stripe、Creem、Waffo 等订单暂不纳入，避免把外币金额当作人民币。

同一订单只能被一份有效申请占用。金额由后台重新计算；未支付、他人订单、重复订单均不能提交。驳回或撤回会释放订单，历史申请仍保留。

## 日常操作

1. 用户提交申请，状态为「待审核」。
2. 管理员核对订单、公司名称及税号，点击「审核通过」，状态变为「待开票」。信息不正确时填写审核说明并驳回，让用户重新申请。
3. 你在日常使用的正式开票系统中人工开具发票。
4. 回到该申请，上传不超过 5 MB 的 PDF 发票，确认后状态变为「已开具」。
5. 用户在申请详情中下载发票。

用户只能撤回待审核申请。已开具发票不能在这里撤回或作废。第一版不自动开票、不发送邮件、不额外扣除用户余额，也没有自动失效或红字发票处理。

## 数据库

启动新版本时自动创建 `invoice_configs`、`invoices`、`invoice_order_claims`、`invoice_orders`、`invoice_files` 五张表，不需要手动执行建表 SQL。数据库账号需要建表及修改表结构权限。保留现有数据库连接和数据卷。

PDF 保存在数据库中，因此数据库备份也包含发票附件。附件会增加备份体积。使用 MySQL 时确认 `max_allowed_packet` 至少为 16 MB，避免较大发票无法保存。

## 宝塔 + Docker 更新

以下命令在服务器终端执行。先在宝塔 Docker 页面确认当前应用的容器、镜像、编排文件位置、数据卷和数据库类型。沿用现有编排配置；仓库里的示例包含默认数据库密码，不要拿它覆盖线上配置。

### 1. 备份

保存当前编排文件、环境变量及旧镜像名称/标签，尤其是数据库连接、会话密钥和加密密钥。备份文件妥善保存在服务器上，不要发送包含密码的配置。

MySQL/PostgreSQL：通过宝塔数据库管理或现有备份工具导出完整业务数据库，确认导出成功。如果数据库在 Docker 中运行，使用对应数据库的备份工具；直接复制运行中的数据库目录不能代替完整备份。

SQLite：短暂停止应用容器后，备份实际挂载的数据目录，再启动旧容器。复制整个目录，包含数据库及可能存在的 WAL 文件；不要在运行中只复制一个数据库文件。

### 2. 构建包含本次代码的镜像

在服务器上取得包含本次改动的仓库版本。首次获取代码可执行：

```sh
git clone --recurse-submodules https://github.com/anlongvip/zhimoapi.git
cd zhimoapi
# 切换到包含发票功能的分支或合并后的提交，再执行：
git submodule update --init --recursive
docker build -t zhimoapi:manual-invoices .
```

已有仓库则在备份后更新到相应提交。镜像构建使用仓库现有 Dockerfile。普通上游镜像不包含这次新增功能，不能通过拉取上游 latest 获得此功能。

### 3. 更新应用容器

在现有编排文件中，只将应用服务的 `image` 改为 `zhimoapi:manual-invoices`。保留端口、数据卷、数据库连接、密钥、网络及数据库服务。若存在自动拉取镜像设置，改为使用本地构建镜像。

在编排文件所在目录执行；下方 `你的应用服务名` 必须换成现有配置中的实际服务名，例如 `new-api`：

```sh
docker compose up -d --no-deps 你的应用服务名
docker compose logs --tail=100 你的应用服务名
```

宝塔界面操作也可以达到同样效果：用新镜像重建原应用容器，并保留原来的挂载和环境变量。不要删除数据库容器或数据卷。

### 4. 上线检查

确认容器启动成功且没有建表错误，原用户、余额和充值记录正常。管理员打开「发票管理」配置开票说明。用已有测试订单验证提交、审核、PDF 上传和下载，再对用户开放。

宝塔网站反向代理的上传上限应允许超过 5 MB 的请求，例如 10 MB，以容纳表单开销。外网使用 HTTPS；如果启用了 `SESSION_COOKIE_SECURE=true`，保留正确的 `SESSION_COOKIE_TRUSTED_URL`，其值为平台完整 HTTPS 来源。

### 5. 回滚

把应用镜像改回备份的旧镜像，重新创建应用服务。新增表可保留，旧版本不使用它们。只有确认数据库损坏、确需恢复备份时才恢复数据库：恢复会丢失备份之后发生的充值等业务数据，应先停服并保存当前数据库。

## 本地验证记录

已验证 SQLite 3.50.4、MySQL 8.4.11、PostgreSQL 17.11 上的订单校验、金额计算、重复申请、状态流转、附件及权限处理，并连续执行两次迁移检查记录保留。路由测试覆盖未登录请求；前端交互测试覆盖合并订单、最低金额及表单校验。

这些是隔离测试数据库，不涉及线上数据。本地未安装 Docker，尚未执行完整镜像构建；首次上线仍需检查实际构建结果、现有数据库权限及宝塔反向代理配置。
